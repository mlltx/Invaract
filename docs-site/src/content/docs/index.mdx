## A verification engine, not a linter

Invaract parses a data contract, translates the engine's own description of a job (a Spark
logical plan, or a Beam pipeline graph) into an engine-independent representation, and checks
the two against each other — structurally, before the write executes. A violation stops the
job. No output is created.

<CardGrid stagger>
	<Card title="The real job" icon="approve-check">
		Verification runs against what the engine is about to execute: Spark's logical plan, or a
		Beam pipeline's graph — not a mock, not a static description of a table.
	</Card>
	<Card title="Enforcement, not just reporting" icon="warning">
		A contract-violating write is stopped *before* it happens, on Spark inside the session and on
		Beam before the pipeline reaches its runner.
	</Card>
	<Card title="No code change to the job" icon="setting">
		A platform team attaches Invaract with a `spark-submit --conf` or a Beam `--runner` option, to
		jobs whose source it doesn't own.
	</Card>
	<Card title="Fails closed" icon="error">
		A write shape Invaract doesn't recognize is rejected, not silently let through unverified.
	</Card>
	<Card title="Never crashes" icon="seti:config">
		Constructs the adapter can't translate degrade to a diagnostic, not an exception — checked by
		property-based fuzzing.
	</Card>
</CardGrid>
