# Invaract Contributor Docs

An Astro Starlight site with the same pleasant, searchable, mobile-friendly reading experience as
[`docs-site/`](../docs-site) — but for contributors to Invaract's own codebase, not users of the
verification engine. It exists because `ROADMAP.md`/`ARCHITECTURE.md`/`docs/**` are plain text
files that are inconvenient to browse, not because their content belongs in `docs-site/`: see
[`../CLAUDE.md`](../CLAUDE.md)'s "Documentation Policy" section for why user-facing and
contributor-facing documentation are kept strictly separate.

## There is no content to edit here

Every page under `src/content/docs/` **except `index.mdx`** is generated by
[`scripts/sync-docs.mjs`](scripts/sync-docs.mjs) from the repository's real source-of-truth docs
(`ROADMAP.md`, `ARCHITECTURE.md`, `docs/**`) — see that script for the exact file list. It runs
automatically before `dev`/`build`. **Never hand-edit a generated page** — the next sync
overwrites it silently. Edit the source file in the repo root or under `docs/` instead, then:

```bash
npm run sync    # regenerate src/content/docs/{project,design,connectors,process}/**
npm run dev     # or: build, preview
```

This keeps the two copies from drifting the way a hand-maintained mirror would: there's exactly
one place each piece of content lives, and this site is a mechanical, always-re-runnable
projection of it (frontmatter added, cross-file relative links rewritten to either an in-site page
or a real GitHub blob URL — see the script's `rewriteLinks`).

## Adding a new source doc to this site

Add an entry to the `PAGES` array in `scripts/sync-docs.mjs` (source path, target slug, sidebar
section/label/order), then add a matching sidebar entry in [`astro.config.mjs`](astro.config.mjs).

## Deployment

Built and deployed by [`.github/workflows/deploy-contributor-docs.yml`](../.github/workflows/deploy-contributor-docs.yml)
into the `contributor/` subfolder of the same GitHub Pages deployment `docs-site/` uses (see that
workflow and `docs-site`'s `deploy-docs.yml` for how the two coexist on one `gh-pages` branch).
