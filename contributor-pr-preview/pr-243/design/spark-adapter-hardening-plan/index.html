Spark Adapter Hardening Plan

This is the record of a battle test of spark-adapter and the plan for closing every gap it found. It is written so that someone who was not part of the test can implement each item without re-deriving anything: every item states what was observed, why it happens, what to build, which tests prove it, and which documents change.

  • Tested at: commit 71554c6 (main), Spark 3.5.9, Delta 3.3.3, Scala 2.12.18, JDK 21.
  • Baseline: ./dev/build passed on that commit, including the whole spark-adapter suite.
  • Method: about 300 adversarial jobs run against a real local[4] Spark session with the enforcement rule installed, plus about 30 real spark-submit runs of PySpark jobs that know nothing about Invaract. Three people were played:
    • the Spark expert — a data engineer who uses every corner of Spark (subqueries, CTEs, streaming, DDL, RDDs, deep plans, concurrency);
    • the newcomer — an entry-level user following the docs: dry run, copy the draft, turn enforcement on;
    • the platform admin — the team that attaches Invaract and an organizational policy to jobs it does not own, and needs to know the attachment holds.

Everything in “Observed” was seen in a real run, not inferred from reading code, unless it is marked (by reading the code). Fixes marked prototyped were tried against the real session and behaved as described.

Implementation record

Section titled “Implementation record”

Every item below has been implemented on the branch that carries this plan, in the order the plan gives (one commit per step; the commit messages name the items). Where the implementation departs from an item’s text, the reason is here, so the plan can still be read as the design.

  • H-10 + dry run. The plan’s own acceptance check (a PySpark job that does DROP TABLE IF EXISTS t and then saveAsTable(t), dry-run, then enforced with its draft) failed as written: saveAsTable writes with the default mode error, the draft declared saveMode: error, and the item’s rule refuses a drop of an output whose save mode is not overwrite. The rule was kept (a hand-written saveMode: error should keep protecting an output); instead the dry-run summary’s merged draft declares no saveMode for an output the job removed data from (DryRunReporter.withoutSaveModeOf). The check now passes, by hand as a real PySpark job and in DestructiveDdlSupportSpec.
  • H-07. A pinned-settings file that names a key Invaract does not read is refused too (a typo would otherwise pin nothing), using H-08’s list of known settings.
  • H-15. Each remote file is fetched once per session and value.
  • H-16. The key is not carried by “same thread, same location, within 60 seconds”: that rule would have merged two real writes of one place, and a probe showed the repeat checks are of two kinds it did not cover. A check made while a checked write is executing finds that write’s plan through Spark’s SQL execution id on the thread (innermost and outermost execution), and a V2 CREATE TABLE ... AS SELECT’s marked-analyzed copy is linked to its unmarked twin (WriteKeys). No version bump: verification-core 0.4.0 is unreleased (the MiMa baseline is 0.3.0), CI compares against the base commit in an isolated Ivy home, and mimaReportBinaryIssues against main’s jar reports nothing new (the existing ContractValidationEvent filters match by method name).
  • H-17f. The validator stops warning for any spelling the type parser maps to a known type; an unknown word still parses (as OtherType) and is still warned about.
  • MiMa (rule 7). mimaReportBinaryIssues against main’s jars reports nothing for contract, verification-core and spark-adapter. Two package-private shapes had changed and were restored rather than filtered: a removal’s dry-run outcome is its own case class (InferenceOutcome.SkippedRemoval) instead of a new field on Skipped, and SparkPlanAdapter.Translator keeps its one-map constructor.
  • Coverage, real jobs (rules 6, 8). spark-adapter 94.67% statements / 91.73% branches (thresholds 92 / 88), with all 1029 tests passing; verification-core 98.53% / 96.75%; contract 94.31% / 90.47%. ./dev/test exits 0 with report status PASS, and ./dev/regression passes all 10 cases.
  • Mutation testing (rule 4). Each new or changed small file was mutated against its own specs only (--test-filter; a filtered run can only score lower than the full suite): TableTargets, DestructiveDdlSupport, SchemaDdlSupport, ReadLocations, PinnedSettings, InvaractSparkPlugin, FailClosedCommands, WriteKeys and InvaractSparkSessionExtension 100%; RemoteFiles 92%, DryRunReporter 93%, SparkConfigSource 76%; verification-core’s changed files 100%. The runs found real gaps, now tested, and one real bug (Spark’s SetTableLocation is an AlterTableCommand whose changes throw for a partitioned V2 table). The survivors left are equivalent (a cache that a mutant bypasses, a log line, an empty list recorded) or in code this work did not change (CsvOptionsSupport.ofWrite). DeepPlans has no scored mutant. The three large files (ContractEnforcementRule, SparkPlanAdapter, WriteCommandSupport) were not mutated locally: a whole-file run with the full suite takes hours here; CI’s incremental job does it for a pull request.
  • H-18. The examples in the dry-run guide and the troubleshooting page that quoted INSERT OVERWRITE DIRECTORY as unrecognized (it is recognized since H-13) were regenerated from a real spark-sql run, with LOAD DATA as the statement Invaract still cannot check.

Order of work

Section titled “Order of work”

Do the items in this order. Each is one pull request unless it says otherwise.

  1. H-01, H-06, H-08, H-12, H-13 — small, independent, no design risk. Do these first to learn the module’s test and CI conventions.
  2. H-09 — makes every later item safer to test on big plans.
  3. H-14 — changes the IR the adapter emits; do it before H-02 and H-03, which build on it.
  4. H-02, then H-03, then H-04.
  5. H-11 — needs H-03.
  6. H-10, then H-05 — they share the “which declared output is this table” helper H-10 introduces.
  7. H-07, H-15, H-16.
  8. H-17, H-18 — H-18 last, because it documents the final behavior of everything above.

H-02, H-03 and H-14 change the IR produced for some queries, so the fingerprint of those jobs changes. Ship the three in one release and say so in its notes (see “Rules for every item”, rule 9).

Rules for every item

Section titled “Rules for every item”

These restate what CLAUDE.md requires, as a checklist. An item is not done until all of them hold. If a step fails and the item does not tell you what to do, stop and report it; do not work round it.

  1. Write the failing test first. Each item names its tests. Write them, run them, and see them fail for the reason the item describes before changing any main code. If a test passes before the fix, the test is wrong or the gap has already been closed: stop and check.
  2. Tests use a real Spark session. Extend ConnectorSpecBase (spark-adapter/src/test/scala/com/invaract/sparkadapter/ConnectorSpecBase.scala) or follow ContractEnforcementRuleSpec: build one SparkSession in beforeAll, call injectContractCheck, switch contracts with withContract(yaml, options) { ... }. Never mock a plan. A test that needs the real --conf path follows InvaractSparkSessionExtensionSpec; one that needs its own JVM (environment variables, exit status) follows DeclaredOutputsSpec and MissingOutputJob.
  3. Assert both directions. Every “X is now rejected” test has a partner “the legitimate neighbour of X still passes”, and the reverse. A rejection test asserts the violation type (e.result.violations.map(_.violationType)) and that the forbidden effect did not happen (the file or table is unchanged), not only that something was thrown.
  4. Mutation testing. For every file you add or change under a module’s src/main/scala, run from that module’s directory sbt 'stryker --mutate "src/main/scala/com/invaract/.../YourFile.scala"' and reach 70%. Write the tests so a flipped comparison, a negated condition, a swapped &&/|| or an off-by-one would each fail one of them; the items name the boundaries that matter.
  5. A new file under spark-adapter/src/main/scala goes into a mutation shard. Add its path to one files: list of the mutation-testing-spark-adapter job in .github/workflows/test.yml. shard-6 and shard-9 hold four files each and are the smallest multi-file shards today; use shard-6 for the first new file, shard-9 for the second, and keep alternating. The mutation-shard-drift-check job fails otherwise.
  6. Coverage. cd spark-adapter && sbt coverage test coverageReport must stay above the thresholds in spark-adapter/build.sbt (92% statements, 88% branches). verification-core has its own (92% and 89%). Never lower a threshold to get a pass.
  7. Binary compatibility. Everything this plan adds to spark-adapter is private[sparkadapter] unless the item says “public”. Do not change the signature of any existing public method or case class. If CI’s api-compatibility job fails, you changed something public by accident: undo it.
  8. Real job. Run ./dev/test (exit 0, demo/output/report.json status PASS) and ./dev/regression. Both must pass after every item.
  9. Documents. Each item lists the pages to change. Besides those: an item that changes what a capability’s note says updates spark-adapter/src/main/resources/invaract-capabilities-spark.yaml and then runs ./dev/capabilities to regenerate the pages built from it; an item that changes the IR for some query shape adds a line to the “Fingerprints change when” list this plan asks H-14 to start in docs-site/src/content/docs/guides/fingerprinting-transformations.mdx. Finish with cd docs-site && npm run build. Read docs-site/DOCUMENTATION.md before editing a page there, and quote only output you produced by running something.
  10. Do not widen the safe list to make a test pass. FailClosedCommands.knownSafe gains an entry only where an item says so, with the reason in a comment next to it.
  11. Do not change verification-core, contract, ir or adapter-testkit unless the item names the file. Most fixes are deliberately kept inside spark-adapter so that the Beam and Python adapters and the conformance kit are untouched.
  12. No new violation type. Every rejection in this plan uses an existing ViolationType, so reference/violation-types.md gains wording, not rows.

  • QueryPlan.subqueries gives the plans of the subquery expressions in one node; collectWithSubqueries(pf) is collect that also descends into them.

  • CatalogV2Util.applySchemaChanges(schema, changes, tableProvider, statementType) returns the schema an AlterTableCommand’s changes produce.

  • org.apache.spark.sql.catalyst.optimizer.InlineCTE(alwaysInline = true).apply(plan) replaces every CTE reference in plan by the CTE’s body.

  • Spark’s META-INF/services loading of SparkSessionExtensionsProvider is not used when the session is created from PySpark (tried: the provider was on the classpath and never called). Do not build on it.

  • A DriverPlugin’s init(sc, ctx) runs before any SparkSession exists, ctx.conf() is the live SparkConf, and a change made to spark.sql.extensions there is honoured by the session created afterwards, from Scala and from PySpark (tried with a prototype plugin).

H-01 DROP DATABASE … CASCADE passes

Section titled “H-01 DROP DATABASE … CASCADE passes”

Severity S1. Small.

Observed

Section titled “Observed”

Under a contract whose declared output is the table dbx.gov_t:

docs/SPARK_ADAPTER.md (“Fail-closed on unverifiable writes”) says dropping a database is deliberately left off the safe list because it “can delete a managed table’s/database’s data”.

Cause

Section titled “Cause”

FailClosedCommands.knownSafe (spark-adapter/.../FailClosedCommands.scala) lists org.apache.spark.sql.catalyst.plans.logical.DropNamespace. That is the class the rule sees for DROP DATABASE, with or without CASCADE. The class the document names, DropDatabaseCommand, never reaches the rule.

Fix

Section titled “Fix”

  1. In FailClosedCommands, remove DropNamespace from knownSafe.

  2. In isKnownSafe, before the set lookup, add case d: org.apache.spark.sql.catalyst.plans.logical.DropNamespace => !d.cascade (turn the if/else into a match). Without CASCADE Spark itself refuses to drop a database that holds a table, so the non-cascade form cannot delete data.

  3. Give the rejection its own words. Change unverifiable(commandClassName: String) to unverifiable(plan: LogicalPlan) and return, for a cascading DropNamespace:

    • problem: DROP DATABASE ... CASCADE deletes every table in the database, so Invaract cannot check it against the contract
    • remediation: Drop the tables this job is allowed to remove one at a time, then drop the empty database without CASCADE.

    Every other plan keeps today’s text (H-17 rewrites that text). Update the caller in ContractEnforcementRule.verifyOrThrow.

Tests

Section titled “Tests”

In FailClosedCommandsSpec:

  • DROP DATABASE d on an empty database passes under a contract.
  • DROP DATABASE d CASCADE on a database holding a table with rows is rejected with UNVERIFIABLE_WRITE, and the table still has its rows afterwards.
  • DROP DATABASE IF EXISTS no_such_db CASCADE is rejected too (state this in the test name: the statement is judged, not what it would find).

Then add one statement-level regression test that runs each of these under a contract and asserts UNVERIFIABLE_WRITE or a write violation, never a pass: DROP DATABASE … CASCADE, LOAD DATA … INTO TABLE, RESTORE TABLE … TO VERSION AS OF 0 (Delta), TRUNCATE TABLE and DROP TABLE on a table the contract does not declare. The existing tests check class names; this one checks SQL text, which is what would have caught this gap. (H-10 later changes what DROP TABLE and TRUNCATE do for a declared output; keep these two on an undeclared table.)

Documents

Section titled “Documents”
  • docs/SPARK_ADAPTER.md, “Fail-closed on unverifiable writes”: say that the list is keyed by the class of the analyzed plan, name DropNamespace, and correct the sentence about DropDatabaseCommand.
  • FailClosedCommands’ own comment block: same correction.

H-02 Reads inside subqueries are invisible

Section titled “H-02 Reads inside subqueries are invisible”

Severity S1. Medium. Do after H-14.

Observed

Section titled “Observed”

Contract: one input orders, rejectUndeclaredInputs=true. sec is a table the contract does not declare.

Query written to the declared outputResultShould be
SELECT id, (SELECT max(id) FROM sec) AS value FROM orderspassesUNDECLARED_INPUT
SELECT id, value FROM orders WHERE id IN (SELECT id FROM sec)passesUNDECLARED_INPUT
SELECT id, value FROM orders o WHERE EXISTS (SELECT 1 FROM sec WHERE sec.id = o.id)passesUNDECLARED_INPUT
SELECT 1 AS id, (SELECT max(value) FROM orders) AS value (default options)MISSING_INPUT for orderspasses

The translated plan shows the subquery as a function with no arguments: Filter(INSUBQUERY(o.id, LISTQUERY())), value = SCALARSUBQUERY(). So besides the input checks, the fingerprint does not change when the subquery changes, and no plan-shape rule (forbid_cross_join, …) sees inside it.

Cause

Section titled “Cause”

A subquery’s plan hangs off an expression, not off the plan’s children. SparkPlanAdapter.Translator.translateExpr falls through to the generic ir.Function(prettyName, children) for ScalarSubquery, ListQuery, Exists and InSubquery, and the plan is not among children. ContractEnforcementRule.collectInputSchemas and collectInputFormats use plan.collect, which does not descend into expressions either.

Fix

Section titled “Fix”

Spark’s own optimizer turns IN/EXISTS into a semi join and a scalar subquery into an outer join. The translation does the same: a subquery becomes the right side of a join placed under the node that uses it. No IR class changes.

All changes are in SparkPlanAdapter.scala and ContractEnforcementRule.scala.

  1. Attach subquery plans. In Translator, rename the body of translateNonWritePlan to translateNode and make translateNonWritePlan this:

    The condition is the literal true on purpose: PlanRuleVerifier treats a join with no condition as a cross join (forbid_cross_join), and this is not one. Check the field names of ir.Project/Filter/Aggregate/Window/Sort/Join in ir/src/main/scala/com/invaract/ir/Plan.scala before writing the copy calls.

  2. Give a scalar subquery’s value its source. In translateExpr, before the generic case e: Expression fallback, add

    The attribute resolves, through the join added in step 1, to the subquery’s own output, so lineage follows it. Leave InSubquery, ListQuery and Exists on the generic fallback: they filter rows and contribute no value.

  3. Find reads in subqueries everywhere a plan is searched. Replace collect with collectWithSubqueries at these four places and nowhere else:

    • ContractEnforcementRule.collectInputSchemas (both calls),
    • ContractEnforcementRule.collectInputFormats,
    • SparkPlanAdapter.computeAliasDisambiguation: the subqueryAliases collect and the bareLeafOccurrences collect,
    • CsvOptionsSupport’s plans.flatMap(_.collect { ... }).

Tests

Section titled “Tests”

New SubqueryReadsSpec (extends ConnectorSpecBase; register temp views over parquet files):

  • the three undeclared-read queries above are rejected with UNDECLARED_INPUT, the message names the subquery’s table, and the output directory is not created;
  • each of the three passes when sec is declared as an input too;

What was tested and held

Section titled “What was tested and held”

So that nobody spends time re-testing these: each was tried and behaved correctly.

  • Writes to a place the contract does not declare were blocked for parquet, json, csv, text, orc, Delta by path, saveAsTable, CREATE TABLE … AS SELECT with and without LOCATION, INSERT INTO, INSERT … VALUES, insertInto, writeTo(...).create(), file and table streaming sinks, and a write through spark.newSession().
  • Hidden reads were found through a join, a UNION, EXCEPT, a CTE, a temp view, a persistent view, spark.table, typed Dataset operations (as[...], map), .cache(), .checkpoint(), .localCheckpoint(), a broadcast hint, a window, LATERAL VIEW, a binaryFile read, a recursive read of a parent folder and SELECT … FROM parquet.\path“.
  • A job cannot overwrite its own declared input (MISSING_INPUT + location mismatch).
  • Ordinary commands pass under a contract: SET, RESET, USE, every SHOW/DESCRIBE, EXPLAIN, temp and global temp views, CACHE/UNCACHE, REFRESH, ANALYZE, MSCK REPAIR, CREATE DATABASE/TABLE, temporary functions, COMMENT ON, table properties, Delta DESCRIBE HISTORY/DETAIL, OPTIMIZE, VACUUM, and the spark.catalog API.
  • Robustness: 2,000-column projections, a 500-way union, eight chained self-joins, pivot, cube, grouping sets, generators, higher-order functions, nested types, JSON functions, window frames, UDFs, typed operations, sampling, hints, unpivot, lateral subqueries, inline tables, odd literals (binary, NaN, intervals, maps) and Delta time travel all verified without error with every option switched on.
  • Concurrency: eight threads each doing 24 writes (paths, saveAsTable, checkpointed) in one session: no error, 256 events, all PASSED.
  • Session handling: spark.newSession() is enforced; spark.conf.set("spark.invaract.…") after the first query has no effect on the session, on a new session, or on a stream.
  • Location forms: trailing slash, file://, file:, a non-normalized write path, and case differences behave as the reference says.
  • Errors a newcomer hits first are clear: no contract set, contract file missing, invalid YAML (the message names the tab character and the line).
  • Dry run to enforcement: a realistic PySpark job (CSV in, join, aggregate, a partitioned parquet output and a saveAsTable) passed under the contract its own dry run drafted, once the DROP TABLE IF EXISTS line was taken out (H-10).
  • One apparent failure, SHOW CURRENT NAMESPACE throwing “Couldn’t find a valid constructor”, reproduces without Invaract once the session has a cached table: it is Spark’s, not ours.

Not fixed, by decision

Section titled “Not fixed, by decision”
  • Reading and writing outside a query plan (RDD actions, foreachPartition, collect). Invisible by nature; documented in H-18.
  • A contract cannot name a view as its input. Declaring the tables under the view works. Supporting the view’s name as well would need an ir.Read to answer to two identities; it is a change to the IR and is left for a separate design.
  • console, memory, noop and .foreach(writer) sinks stay rejected. They have no location to check. H-17a improves the message.
  • Sensitivity tags are reported, not enforced. Already stated in the contract format reference; H-14 makes the report correct, which any future enforcement rule depends on.
  • Kafka, rate and other non-file sources inside foreachBatch. H-11 records what happens and documents it.
  • Duplicate checks when the extension is listed twice are removed by H-07; nothing else.
  • Spark Connect, Iceberg- and Hive-specific forms of the statements in H-05 and H-10, and cluster managers other than local were not exercised in this test. Where an item matches a catalyst class (AlterTableCommand, DropTable, TruncateTable) the Iceberg form is covered by construction; add one Iceberg test per item in IcebergConnectorSpec to confirm, and record anything that differs in docs/connectors/iceberg.md.
