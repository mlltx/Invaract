Use Invaract with Beam Python Pipelines

This guide checks an Apache Beam pipeline written with the Python SDK against a data contract before the pipeline is submitted, and shows how a platform team turns that on for a job whose source it does not own. The contract is the same YAML you write for Spark or for a Java Beam pipeline.

What this does and does not check

Invaract reads the shape of a Python pipeline: where it reads, where it writes, which columns and types come out, and in which format. It cannot read what your own Python functions do, so the transformation-shape rules (required_filter_columns, required_join_columns, required_group_by, forbid_cross_join) are refused with UNSUPPORTED_CONTRACT_FEATURE rather than checked. It recognises reads and writes of Parquet, Avro, text and TFRecord files, BigQuery tables and Pub/Sub topics. The full list is in Engine Capabilities (the beam-python column).

How it works

Section titled “How it works”

Your job is unchanged. Two flags switch the check on:

  • --runner=invaract_beam.InvaractRunner makes Beam hand the finished pipeline to Invaract’s runner, before any step has run.
  • --invaract_delegate names the runner the pipeline goes to once it passes (DataflowRunner, FlinkRunner, …). The default is the DirectRunner.

The runner writes the pipeline’s portable form (the language-neutral description every Beam SDK produces) to a temporary file and runs Invaract’s checker on it. The checker is a Java program, the same code that checks Java pipelines, so Java 11 or later must be installed where the job is submitted. If the checker refuses the pipeline, or cannot run at all, the job does not start.

The adapter is tested with the Python SDK of Beam 2.68.0, 2.71.0, 2.74.0 and 2.77.0. A streaming pipeline that writes files needs 2.68.0 or later, the first release whose WriteToParquet takes triggering_frequency.

The settings

Section titled “The settings”

Every Invaract setting is a flag of the job, spelled --invaract_<setting> (all values are text, so a switch is --invaract_dry_run=true):

FlagWhat it does
--invaract_contractThe contract to enforce: a file path, or registry://<id>@<version> (Use a Contract Registry).
--invaract_dry_run=trueInfer a contract from the job’s writes instead of enforcing one (Dry-Run Mode).
--invaract_notify_configWhere validation events go (Notification Sinks).
--invaract_location_mapHow ref:// locations resolve (Resolve Dataset Locations).
--invaract_org_policy, --invaract_org_policy_overlaysOrganizational policy layered on the contract (Enforce Organizational Policy).
--invaract_reject_undeclared_inputs=true, --invaract_reject_undeclared_fields=trueStricter checking of reads and columns.
--invaract_trusted_stepsSteps that end the pipeline without a write that a platform trusts (see below).
--invaract_registry_url, --invaract_registry_client_classThe contract registry.

And how the checker is run:

FlagWhat it does
--invaract_delegateThe runner a passing pipeline is handed to. Default: DirectRunner.
--invaract_checker_jarThe checker jar. Default: the INVARACT_BEAM_CHECKER_JAR environment variable.
--invaract_javaThe java program. Default: $JAVA_HOME/bin/java, else java on the PATH.
--invaract_java_optionsOptions for the checker’s JVM, such as -Xmx512m.

Where locations come from

Section titled “Where locations come from”
  • A file read is located at the folder its pattern reads: data/in/orders/*.parquet reads data/in/orders.
  • A file write is located by its pattern up to the shard template: WriteToParquet("data/out/report") writes data/out/report-00000-of-00001.parquet, located at data/out/report.
  • A BigQuery table project:dataset.table is project/dataset/table, registered in the bigquery catalog.
  • A Pub/Sub topic or subscription is its full path (projects/p/topics/t).

Formats, types and what cannot be told

Section titled “Formats, types and what cannot be told”
  • Columns are known when the write states the schema it writes (a Parquet write’s pyarrow schema, an Avro write’s schema, a BigQuery load’s table schema) or when the data is typed Beam rows (ReadFromParquet(..., as_rows=True), a beam.Map(...).with_output_types(...) that yields rows). A write of plain Python dictionaries states no columns: if its output declares columns, the write is refused rather than passed unchecked. A beam.Select with a computed field has an untyped column, which counts as unknown.
  • Formats are the sink a write uses. A text write cannot tell CSV from JSON.
  • Save modes: only a BigQuery write states one (WRITE_APPEND, WRITE_TRUNCATE, WRITE_EMPTY are append, overwrite, error). A contract that declares a save mode for a file write has that write refused.
  • Reads that state no location are still seen, never mistaken for data the job makes: a CSV read through pandas (ReadFromCsv), a BigQuery query, a source class Invaract does not know, files matched by fileio (MatchFiles, MatchContinuously), a classic template’s parameter. A declared input such a read may be is reported unverifiable rather than missing, and with --invaract_reject_undeclared_inputs=true the write is refused.
  • Writes Invaract cannot place are refused: a CSV write through pandas (WriteToCsv), fileio.WriteToFiles, a BigQuery write whose table the job computes, a classic template’s parameter.

Steps that end the pipeline

Section titled “Steps that end the pipeline”

A step that ends the pipeline without being a write Invaract recognises (a beam.Map(print), a call to a service) is refused, because it may move data where the contract cannot see. Two kinds are let through, exactly as for Java pipelines: a step that reads only what a write reports (the file names a write produced), and a step a platform names as trusted: --invaract_trusted_steps=Notify*,Metrics.

When the command line cannot reach the job

Section titled “When the command line cannot reach the job”

A job that sets its runner in code (PipelineOptions(argv, runner="DirectRunner")) or does not pass its command line to Beam is not checked: the flags never reach it. A job submitted from a machine without the package does not start (ModuleNotFoundError: No module named 'invaract_beam'), and one submitted without Java stops with CheckNotRun.
