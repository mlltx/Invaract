Write a Contract

An Invaract contract is a YAML document describing a transformation’s inputs and outputs — shaped after the Open Data Contract Standard (ODCS), not a new format invented from scratch. This guide builds one up using the real contract this repository ships, demo/contracts/invaract_output.yaml.

Tip

Don’t want to start from a blank file? Dry-run mode runs your transformation with no contract at all and prints one back, built from what it actually read and wrote — a real draft to edit rather than a template to fill in.

Start with identity and version

Section titled “Start with identity and version”
  • id — a stable identifier for this contract.
  • version — MAJOR.MINOR[.PATCH], as a string ("1.0.0" or "1.0").
  • status — free-form; defaults to active if omitted.

Declare inputs

Section titled “Declare inputs”

Each input is a dataset the transformation reads:

  • name — logical name, used for lookups and violation messages.
  • location — the physical location Invaract matches against the real Spark plan (a table name or a file path). Spark reports absolute file: URIs at runtime; a relative location declared here still matches, by suffix — see Contract Format.
  • format — optional, e.g. csv, parquet, delta.
  • schema.fields — at least one field, each with a name and type.

Declare outputs

Section titled “Declare outputs”

At least one output is required — this is what a contract actually gates:

saveMode (append/overwrite/ignore/error) is checked against the write’s actual save mode when both are known.

Field semantics

Section titled “Field semantics”
KeyDefaultMeaning
requiredfalseThe field must be present in the actual schema.
nullable!requiredThe field’s values may be null.
properties—Nested fields, for a struct type.

Caution

Marking a field both required: true and nullable: true is legal — Invaract warns about it (it’s an unusual combination) but doesn’t reject the contract.
